# Pluggable Connectors

Beyond cloud and Git, Alethia supports **pluggable per-category connectors** that let a Project mix in the tools you already use instead of the cloud-native default — Cloudflare for DNS, HashiCorp Vault for secrets, Docker Hub for a registry, a private Helm or OCI source for charts, and Datadog / Grafana Cloud for observability.

These connectors authenticate with an **API key / token** (`auth_method = api_key`) rather than cloud federation or OAuth.

## Categories and providers

| Category | Cloud-native default | Pluggable provider | Credential fields |
|----------|----------------------|--------------------|-------------------|
| **DNS** | Route 53 / Cloud DNS / Azure DNS | **Cloudflare** | API token |
| **Secrets** | Secrets Manager / Secret Manager / Key Vault | **HashiCorp Vault** | Address, token |
| **Registry** | ECR / Artifact Registry / ACR | **Docker Hub** | Username, access token |
| **Chart repositories** | — (public charts need no credential) | **[GitHub Container Registry, Docker Hub, GitLab, Scaleway, generic OCI, HTTPS](/console/connectors/chart-repositories)** | Username, password / token |
| **Observability** | — (none) | **Datadog** | API key, app key |
| **Observability** | — | **Grafana Cloud** | Instance ID, API token |

The catalog is data-driven — each provider is one row in the `connectors` table, seeded from a single manifest (`packages/core/categories/catalog.json`). See [Connectors Architecture](/concepts/connectors) for how this works end to end.

## Connecting a provider

1. Open **Connectors**, pick the provider card, and choose **Connect**.
2. Fill in the API credential — the form fields are generated from the provider's credential specification.
3. Alethia runs a lightweight **verification ping** against the provider's API (e.g. Cloudflare's token-verify endpoint, Vault's token lookup, Docker Hub login, Datadog's key-validate endpoint). A verified credential turns the card green; an unverified one is still saved so you can retry.

## How credentials are stored

Secret fields (tokens, passwords) are **encrypted at rest** with AES-256-GCM before being written to the `connector_credentials` table; non-secret fields (a Vault address, a Docker Hub username) are stored in clear. The encryption key comes from `ALETHIA_CRED_ENCRYPTION_KEY` (see [Configuration](/self-hosting/configuration)).

<Callout type="info">
Secrets are **never** placed in a Project's `config_snapshot`. They are decrypted and attached to a job only at **claim time**, then injected into the runner's OpenTofu variables in memory — preserving the [zero-credential model](/concepts/security).
</Callout>

## Using a connector in a Project

Once connected, pick the provider per component in the [Project designer](/console/design-project):

- [DNS & WAF](/console/design-project/dns) — choose **Cloudflare** instead of cloud-native DNS.
- [Secrets](/console/design-project/secrets) — choose **Vault**.
- [Container Registry](/console/design-project/container-registry) — choose **Docker Hub**.
- [Chart repositories](/console/connectors/chart-repositories) — add one per environment so Alethia can read your private charts.
- [Observability](/console/design-project/observability) — choose **Datadog / Grafana Cloud**.

At provision time the runner composes the chosen provider's module into the plan and **skips** the cloud-native resource for that category.

### Chart repositories

A chart repository works differently from the categories above: it provisions nothing. It tells Alethia which credential to use when ArgoCD pulls a Helm chart from a private repository.

1. Connect the provider under **Chart Repos** on the Connectors page.
2. On the Project canvas, add a **Chart repository** component (**Add → DevOps → Chart repository**) and pick the connected provider. Providers that serve a single fixed host — GitHub Container Registry, Docker Hub — need nothing more. For a self-hosted or generic registry, give the bare registry host (`registry.acme.io`, no scheme and no path); for an HTTPS Helm repository, give the full `https://` URL.
3. Deploy. Before it syncs any chart, the runner writes an ArgoCD **repository credential** for that repository. ArgoCD matches a chart to a credential by URL prefix, so the host you enter must match the host your charts are addressed by.

You need one only for a **private** repository. Public charts, including everything in the add-on marketplace, pull without a credential.

To use a private chart, attach it with **Add → Bring your own Helm chart**, choose **OCI registry**, and give the whole reference including the chart name (`oci://ghcr.io/acme/payments`) plus a chart version (`*` for the latest). The dialog tells you whether a chart repository on the environment covers that host.

A chart pulled from an OCI registry is scanned exactly like one in a Git repository, and the same credential authenticates both the safety scan and ArgoCD's deploy-time pull. See [Chart repositories](/console/connectors/chart-repositories) for the full provider list and how a chart's host is matched to a credential.

## Adding a new provider

Pluggable connectors are an open-ended catalog. Adding a sixth provider takes four steps and **no** changes to routes, the runner core, or the form engine:

1. Add a row to `packages/core/categories/catalog.json` (category, slug, auth_method, icon, credential + provider_config fields). Set `icon_url` to a path under `packages/assets/static` — the convention is `/icons/<slug>/<slug>-32x32.png` — after committing the file there, or to `null` if no mark ships for the provider. `null` renders a monogram tile and issues no request; a path with no file behind it is rejected in step 4.
2. Add a `CategoryProvider` Go impl under `packages/core/categories/` (its `Tfvars`/`Validate` behavior).
3. Add the OpenTofu module under `infra/templates/categories/<category>/<slug>/`. A chart-repo provider has no module — it implements `RepoCred` instead, and must also get a host rule in `apps/console/lib/connectors/helm-registry-hosts.ts` so the console resolves the same credential URL the Go provider seeds.
4. Run `pnpm -F console gen:connectors` to regenerate the registry + catalog seed. It fails, naming the connector, if any `icon_url` does not resolve to a committed file under `packages/assets/static`.

See [Connectors Architecture](/concepts/connectors) for the contract details.
