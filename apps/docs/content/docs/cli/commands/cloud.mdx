# Cloud Commands

The `cloud` group reads the **inventory** Alethia discovered in a connected cloud account — the
networks (VPCs/VNets), subnets, and regions it swept.

<Callout type="info">
The CLI is a client of the same Console API. `cloud inventory` calls
`/cli/cloud-identities/<id>/inventory` with your [CLI token](/cli/authentication) and operates on
the **active organization** — the cloud identity must belong to it.
</Callout>

## `alethia cloud inventory`

Show the discovered networking + regions for a connected cloud account.

```bash
# Name the account by its provider
alethia cloud inventory aws
alethia cloud inventory gcp -o json

# Or omit the argument for a picker over your connections
alethia cloud inventory
```

| Argument | Required | Description |
|----------|----------|-------------|
| `[provider]` | No | `aws`, `gcp`, `azure`, `alibaba`, or `hetzner`. Omit for a picker. A cloud-identity id is still accepted. |

<Callout type="info">
**No id to copy.** This command used to take a bare `<cloud-identity-id>` — an opaque token
you had to copy out of another command's output before you could run it. Naming the provider
does the lookup for you, and omitting the argument shows a picker. An id a script already
holds keeps working, byte for byte: an id is a lookup key, so nothing here rewrites one.

Under `--no-input` there is no picker to show, so the argument is required and the refusal
says which providers are valid. If two accounts are connected for the same provider, the
command reports the ambiguity and lists their ids rather than guessing.
</Callout>

Renders a **Networks** table (network id, name, region, CIDR, default), a **Subnets** table
(subnet id, name, region, AZ, CIDR, public), and a **Regions** line. Add `-o json` for the full
inventory object; `-o csv` emits the networks rows. Prints `No cloud inventory discovered yet.`
when the account hasn't been swept. Backing call: `GET /cli/cloud-identities/<id>/inventory`.
